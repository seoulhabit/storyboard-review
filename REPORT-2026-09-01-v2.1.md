## 1. Phase 1 — the engine layer, and the render proof rerun

### 1.1 What the contract actually is

`references/hyperframes-engine.md` (273 lines) is a transcription with the source
file named beside every line. The load-bearing corrections to v2:

| v2 said | The shipped engine |
|---|---|
| `data-time-start` / `data-time-duration` / `data-offset` | `data-start` / `data-duration` on `class="clip"` elements *(docs/data-attributes.md §Timing)* |
| a hand-written `function seek(t)` registered as `window.seek` | `gsap.timeline({paused:true})` registered on `window.__timelines[<id>]` *(docs/gsap.md, templates/blank/index.html, AGENTS.md rule 3)* |
| absolute `file:///ABS/PATH` and `/mnt/...` | project-relative paths resolved via `hyperframes.json` `paths` *(docs/compositions.md, AGENTS.md rule 5)* |
| "never rely on a webfont CDN at render time" | a named Google Fonts link **is** the supported path — the compiler injects deterministic `@font-face` at render time |
| GSAP CDN implicitly discouraged | GSAP from jsdelivr is the shipped blank template's own pattern |
| — | `data-track-index` is a **Studio display lane the render never reads** *(docs/data-attributes.md L9)* |

`hyperframes beats` is **not** a beat-sheet path, as the brief's fallback
anticipated: per `hyperframes-cli/references/beats.md` it is a Studio *music*
utility that analyses a local audio track and writes a beat grid, fails without
one, and has nothing to do with a story beat sheet. So `scripts/beats_to_composition.py`
(492 lines) is ours. It turns `03-beat-sheet.json` into `index.html`, one
sub-composition per scene, and the `*.motion.json` sidecar — timing is never
hand-typed, and its three validators exit non-zero and write nothing on failure
(frozen tail, non-tiling scenes, scenes-vs-VO mismatch; all verified).

### 1.3 What the engine caught in my own first pass

My first generator emitted `tl.set(el, {opacity:0}, 0)` — the idiom the working
reference scene uses, adopted on the strength of the audit's `fromTo` +
`immediateRender:false` finding. Lint rejected it:

```
gsap_timeline_set_initial_hide: Initial hidden state for "#s01-b1" is set via
tl.set(...) at position 0 inside the paused timeline. A zero-duration set at 0
does not render while the playhead sits exactly at 0, so frame 0 shows the
un-hidden state.
```

So the reference project's fix for one frame-zero bug installs its mirror image.
The state that survives a cold seek to 0 is authored **outside** the timeline —
in CSS, restated with `gsap.set()` — with the timeline only ever tweening toward
visible. The 0.2 s frame proves it: hook line alone, second beat absent until
1.0 s. Both halves of the trap are now written into the engine reference as a
two-row table, because knowing only one of them produces the other bug.

```

without saying which wins. This mix cannot reach -14 under a -2.5 dBTP ceiling:
integrated -25.55 with true peak -7.14 needs +11.55 dB, which would put the peak
```

### 4.4 A defect in the skill's own tool, found by pixels

`extract_frames.sh` derived duration from `format=duration`, which on a muxed
file is the **longest stream** — here audio at 46.300 s against video at
46.267 s. The last-frame seek landed 33 ms past the final video frame: ffmpeg
wrote nothing and **still exited 0**, so `set -e` never fired and `frame-last.png`
was silently absent. Fixed to read the video stream's own duration, back off
0.10 s, and treat a zero-byte output as a hard failure.

The skill's own rule turning on the skill's own tool: the log said the frames
were extracted; the directory listing said otherwise.

### 4.5 What the dry run does not prove

The pipeline produced a **correct** video, not a designed one. Because the
generator emits entrance-only motion on a kinetic-type presenter, the render is
centred type on flat ground for 44 seconds. It passes every gate — which is the
point of the gates — and it does not reach the channel's clinical-minimalist
register. Extending the generator to moving-diagram and data-object presenters,
and to sustained (not entrance-only) motion, is the named follow-on.

## 6. The claim-sourcing rule — `K-*`

Written after the dry run, into `decision-policy.md` §Claims. It is the answer to
`BLOCKER-CLAIM`, and it is a **floor that applies whether or not a project skill
exists** — `SKILL.md`'s delegation sentence now says so explicitly. v1 stated the
gap in prose and left the rule unwritten; v2 deleted the prose; this closes it.

**Grounded in what the repo already does**, not invented:

- `videos/peeling-not-progress` is the exemplar — a dedicated pass fetched and
  confirmed every citation URL live, and **two claims required rewording before
  build "because the brief's original wording said the opposite of the cited
  regulator."** That is what sourcing is for, and it is why `K-1` says an
  identifier nobody has read is not a source.
- `catalog/visual-components/unsourced-flag/` records the same disclosure concept
  converging independently across **six** shipped videos with six different
  visual treatments — so `K-2` names one.
- `videos/centella-tiger-grass` §Round 5 is the failure case: flags deleted,
  claims kept. That is why `K-2b` exists.

| Rule | What it does |
|---|---|
| **`K-1`** | Every assertion is classified before the script is written — nominal / sourced / unsourced / illustration / editorial — into `01-story-brief.md` §Sourcing, in the exemplar's table shape. Unclassifiable defaults to **unsourced**. |
| **`K-2`** | An unsourced claim may render only if it is **attributed** in words, carries a **concurrent** flag (muted, never the accent, never citation typography), and is not hard-prohibited. |
| **`K-2a`** | Hard prohibitions no flag rescues: unsourced **safety** claims *scaled to risk*, treats/prevents/cures, an unsourced **number**, comparative superiority, absolute language. These are sourced or **cut**. |
| **`K-2b`** | If unsourced ≥ sourced across Mechanism and Proof, the video may not present as an explainer of how the thing works — it takes the **disclosure-forward** form, stating the absence in the narration. A badge on every sentence is wallpaper. |
| **`K-3`** | The attribution verb appears in the VO **and** the on-screen type, and the on-screen wording hedges **at least as far as** the voiceover — 88.1 % of this channel's views are muted-first, so the type is the claim most viewers receive. |
| **`K-4`** | A reading gate on extracted frames at S7. `check` has no notion of a claim and cannot do any of this. |
| **`K-5`** | The description and pinned comment carry the posture — a disclosure only inside the video is not a disclosure to anyone reading the page. |

### It failed my own shipped render, which is the point

Run back over the first cut's 11 claim rows: **6 failed**. Three causal claims
asserted rather than attributed and unflagged; one attributed but unflagged; one
flagged 5.1 s into a 6.6 s scene rather than concurrently; one usage instruction
unattributed. A rule that had blessed what I already shipped would have been
worth nothing.

The run was then re-executed under it and now passes. Two things changed that are
worth naming:

- **The hook.** The first cut opened on "Your skin isn't sensitive. It's a broken
  barrier." — an unsourced diagnostic claim asserted as fact at frame zero.
  `K-2` does not permit it. The fix is the question form, "Is your skin actually
  sensitive? / Or is the barrier damaged?", which is **independently supported**:
  it is T-4 shape rank 3 (breakoutScore 271.05) in the channel's own outlier set.
  The rule and the data pointed the same way.
- **`K-2a` was calibrated by the test.** Its first draft would have cut "Start
  cica, daily, on damp skin" outright, because it contained a frequency. That is
  wrong — cica is a non-active and the instruction is low-risk. The bullet now
  scales to **harm from getting it wrong**, not to whether the sentence contains
  a frequency, with the calibrating case named in the rule.

### And the pixel gate caught the fix's own regression

The re-cut split the hook question across two scenes, so frame zero shipped
"IS YOUR SKIN" alone — not a complete thought, a breach of mandatory rule 5.
`check` passed **0 errors, 0 warnings** on that version. Extracting frame zero
caught it. The hook is now one scene and frame zero carries the whole question.
