## Reproducing

```bash
python3 scripts/retime_vo.py          # raw/ -> working takes at atempo 1.15
python3 scripts/pad_vo.py             # uniform 250ms tail
python3 scripts/build_frames.py       # compositions/frames/*.html
python3 scripts/build_index.py        # index.html
python3 scripts/build_storyboard.py   # STORYBOARD.md (parses index.html)
python3 scripts/build_script_md.py    # SCRIPT.md (from vo_lines.py)
python3 scripts/build_captions.py     # captions/*.srt + .vtt
python3 scripts/build_bgm.py          # bed cut to the real root duration
npx --yes hyperframes@0.8.22 check --samples 60
npx --yes hyperframes@0.8.22 render --quality high --workers 1 -o renders/raw.mp4
python3 scripts/master-audio.py . renders/raw.mp4 renders/collagen-where-did-it-go_final.mp4
```

`index.html` and `compositions/frames/*.html` are **generated**. Editing them
directly survives a render and is discarded by the next build — edit the
generator. Both emit a header comment saying so.

**The QC gates need `--landscape` / `--longform`.** Without them the bottom-zone
slice runs past the end of a 1080-tall array, numpy returns an empty view, and
the hard gate prints "no findings" and exits 0 — a silent false pass.

## Runtime — how it got here

Three settings, in order, each recorded because the number moved for a reason:

| | Runtime | atempo | SoulHabit / Jay |
|---|---|---|---|
| First cut | 3:24.30 | 1.15 | 161 / 152 wpm |
| Trimmed to 3:00 | 3:00.000 | 1.265 | 176 / 166 wpm |
| **Shipped** | **3:09.000** | **1.20** | **168 / 158 wpm** |

The 3:00 cut hit its mark, but at 176 wpm SoulHabit sat above the normal
150–170 explainer band and read as hurried on the longer claim sentences. Dialled
back to 1.20 on request: both voices are now inside the band, at the cost of 9
seconds. **No scripted line was ever removed at any setting.**

The fixed overhead stays where the 3:00 trim left it — cold open floating,
end-card hold at its 5.0s floor, lead/tail/gap tightened — because none of that
was costing anything audible, so there was no reason to give it back:

| Lever | Original | Now |
|---|---|---|
| Cold open | 5.00s | 4.67s (floating) |
| End-card hold | 7.00s | 5.00s (floor) |
| Scene lead-in / tail | 0.35s / 0.55s | 0.25s / 0.40s |
| Turn-taking gaps | ×0.68 | ×0.36 |

**The cold open is the balancing term.** It is the only wordless scene, so its
exact length is free: `scene_timing()` clocks every other scene from its VO and
gives the cold open whatever remains to land the root on exactly `TARGET_TOTAL`,
clamped to 3.2–6.0s, with its own beats scaled to whatever length it gets.
Re-record a line and the piece still lands on the target without anyone
re-deriving anything.

To change the pace: set `TEMPO` in `scripts/retime_vo.py` and `TARGET_TOTAL` in
`scripts/build_frames.py`, then rebuild. The raw takes in `assets/voice/raw/` are
never modified, so the retime is idempotent and any tempo is one constant away.

## Bugs this build surfaced

Each was caught by a specific check and verified against pixels, not reasoned about.

1. **`LANE_CSS` was defined and never included.** Every scene fell back to the
   in-flow `.lane` rule in BASE, so cards stacked in the flex row and the first
   card of each scene rendered off-frame entirely. An unreferenced CSS constant
   is not a lint error; caught by snapshot extraction.
2. **`will-change: transform` silently made the lane stack an `offsetParent`,**
   so a measured scroll offset was taken against the stack rather than the
   viewport and every card sat ~213px high. Fixed twice: first by walking the
   offsetParent chain, then by removing measurement altogether in favour of
   `yPercent` anchoring, which resolves against each element's own height and
   cannot go stale when a line is reworded.
3. **31 × `gsap_non_transform_motion`** — the first lane mechanism animated
   `height`/`marginTop`/`padding` to make room. Layout properties snap to integer
   device pixels and stutter under a seek-by-frame capture.
4. **Scene 05 hid its own dialogue for six lines.** The phase wrapper that faded
   out at the verdict contained the lanes as well as the actor, so L36–L41 spoke
   with no card on screen. Caught by the motion sidecar's `appearsBy` on
   `#L38 .say` — which is precisely why assertions name copy elements and not
   their containers.
5. **Two frozen windows over 6s**, both mid-payoff: 04-evidence held for 6.6s
   across the 23-trials line, and 05-verdict for 6.15s across the
   sunscreen/smoking/nutrition line. Both were lines that name several things and
   carried one beat. Caught by `keepsMoving`, invisible to the eye on a scrub.
6. **Scene 04's dialogue rail was too short**, guillotining cards mid-sentence,
   and its flex column squeezed the verdict bar to a 9px sliver with a card drawn
   over it. Rebuilt as explicit grid rows — grid rows cannot overlap, and
   `minmax(0,1fr)` decides which row gives way.
7. **Consecutive same-speaker cards overlapped unreadably for ~0.4s**, because
   the outgoing card began clearing at the same instant the incoming one landed.
   The exit now leads the entrance by 0.28s.
8. **The inherited `pad_vo.py` matched nothing.** Its glob was `[0-9][0-9].wav`
   from a single-voice project; this one names takes `NN-<speaker>.wav`, so it
   reported "0 takes normalised" as though the job were done.
9. **The catalog's static-hold checker carried another project's provenance.**
   Its docstring named `peeling-question-open` as "this project" — the fourth
   recurrence in that file's lineage, three of them with a warning comment
   already in the file. Replaced the comment with a runtime assertion that
   refuses to run when `CAPTION_BAND_EXCLUDE` disagrees with the project's own
   markup, and proved it fires in both directions.
10. **The BGM bed's last ~12s is an authored fade to digital silence**
    (−41 → −96 dB), sized for its original running time. Only the live body is
    used, looped to this edit's real length with our own declick edges.

11. **A camera that ENDS zoomed leaves the scene permanently cropped, and the
    hard safe-area gate cannot see it.** `.worldclip` clips at the safe line, so
    scenes 01 and 02 — whose cameras settled at scale 1.045 and 1.02 — had ~17-39px
    shaved off each edge for the rest of the scene. A full-resolution crop showed
    02-door's note rendering as *"locks are labelled"* with the B cut off. The
    gate reported a clean pass throughout, and correctly: the clip removes the
    offending pixels *before* the gate looks, so cropped content reads to it as
    perfect compliance. Only the phone-scale legibility pass surfaced it. Every
    camera now settles at scale 1.0.
12. **The tile pictogram was being crushed to 12px rows.** As
    `minmax(0,1fr)` it was the row that gave way to every other row, which also
    made it too small to carry a beat — 8 tiles came to 1.2% of frame and
    measured 0.6 per step against a 1.0 floor. An explicit height makes the
    pictogram the thing the layout protects, which is right: it is the scene's
    subject.
13. **`rm -rf renders/work-*` silently did nothing when the glob had no match.**
    zsh aborts the whole command on a failed glob, so `raw.mp4` survived, a
    file-existence wait returned immediately, and a *previous* render got
    mastered and gated twice. Use `find -exec rm -rf {} +`, and wait on a
    sentinel in the render log rather than on the output file — HyperFrames
    creates `raw.mp4` before it finishes writing it.

## Known findings, verified as false positives

**Layout auditor, 4 × `content_overlap` in 04-evidence.**
Every reported timestamp was extracted and inspected: the frames are clean. The
auditor tests bounding boxes and does not model `overflow: hidden`, so a lane
card clipped above its band still presents a box that intersects the verdict bar.
This is the same family as the documented `clip-path` wipe false positive.
**Do not restructure the composition to satisfy these** — confirm on a frame.

**Region-aware static-hold, 4 content-voids.** Three of them
(t=196.50-204.00, t=199.00-204.00, t=196.75-204.00) are the closing scene's
**end-screen reserve** — that zone is *required* to be clear so YouTube's own
overlay elements land on empty frame, so the finding is the design working. The
fourth (t=65.00-69.25, upper right) is negative space at the end of 02-door,
where the door and the size cards sit left and the dialogue sits centre-right;
verified on an extracted frame.
