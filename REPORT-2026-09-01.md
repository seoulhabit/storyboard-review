## 4. Skill audit — v2

### 4.1 The headline finding: v2's engine contract does not match the shipped engine

v2's `hyperframes-engine.md` and `assets/composition-skeleton.html` specify
`data-time-start` / `data-time-duration` / `data-offset` driven by a hand-written
`function seek(t)` registered as `window.seek`. The installed `hyperframes@0.8.19` drives
**paused GSAP timelines registered on `window.__timelines[compositionId]`** — confirmed
this session against `npx hyperframes@0.8.19 docs data-attributes` and against every
project in this repo that renders.

**Tested, not asserted.** I built a minimal composition directly from v2's own skeleton
(kinetic type only, so no asset or font path could confound the timing question): three
scenes, three distinct background colours, 9 s.

*As written*, `hyperframes check` rejects it with three errors, the third naming the
contract outright:

```
✗ root_missing_composition_id     ✗ root_missing_dimensions
✗ missing_timeline_registry: Missing `window.__timelines` registration.
   Fix: Register each composition timeline on `window.__timelines[compositionId]`.
```

I then gave it the charitable fix — added the root wrapper attributes so the engine would
render it — and kept v2's `seek(t)` model. It rendered, after this warning:

```
[sub_timeline_readiness_timeout] Sub-composition timelines did not become ready within 45000ms
9.0s video · 18.0 KB
```

Frames extracted at 0.2 / 1.5 / 4.5 / 7.5 / 8.8 s are **pixel-identical**, mean |Δ| =
**0.00**, all flat `rgb(24,75,59)` — scene 1's background. Scenes 2 and 3 never appear;
scene 1's own headline never appears either, because `seek(0)` sets `--p` to 0 and nothing
ever advances it.

**A v2-shaped composition renders as a single flat colour for its entire duration** — the
exact "preview looks great, the MP4 is frozen" failure v2's own mandatory rule 1 exists to
prevent.

The cross-check is the part that matters:

| Composition | v2's `lint_composition.py` | `hyperframes check` | Actual render |
|---|---|---|---|
| v2-shaped (from v2's skeleton) | **PASS** — 0 errors | **FAIL** — 3 errors | **Frozen**, Δ = 0.00 |
| v1-shaped (my working hook scene) | **FAIL** — 3 errors | **PASS** — 0 errors | **Correct**, 21/21 contrast |

v2's lint is exactly inverted against reality on this engine. Its three errors on the
working composition are each false here: `window.seek` is not the engine's entry point;
the relative image path loaded correctly (the plate is visible in the extracted frames);
and the Google-Fonts link rendered correctly because the engine injects deterministic
`@font-face` for named Google Fonts at render time.

v2 does say the attribute names are "this project's convention" and instructs verifying
against installed docs. That hedge does not survive `lint_composition.py` **erroring** when
`window.seek` is absent — the lint enforces the unverified convention as a gate.

114 s** — against a channel per-video median of 61.28 %. **Retention is above median.**
v1 diagnosed a retention failure on a video that retains better than three quarters of the
channel, because it inferred retention from view velocity after concluding the metric was
unavailable.

Which of v1's eight findings survive v2's checkpoints: the payoff-at-13.5s and the

### 4.5 Other defects found in v2

- **`[S1/S-2]`'s baseline override is self-defeating.** It sets short target length from the
  median duration of top-quartile videos by avg-view-%. Measured here that is **19 s** —
  below the rule's own 30 s clamp floor. And the metric counts replays (6 of 34 shorts
  exceed 100 %, one at 603.86 %), so shorter videos score higher mechanically. The override
  would ratchet target length down on every readout.
- **`[S1/S-1]` defaults to long-form** when the baseline is empty. This channel is 46/48
  Shorts with 88.1 % of views from the Shorts feed. The default is backwards for exactly
  the channel the pipeline is aimed at.
- **`[S2/T-3]` uses `maxSubscribers = 10 × subs`.** Here that is **80** — an outlier search
  capped at 80-subscriber channels returns nothing usable. The rule has no floor.
- **The traffic schema cannot represent a Shorts channel.** `browse/suggested/search/
  external` has no slot for the Shorts feed, 88.1 % of views.
- **`p75_48h` does not exist.** `vidiq_channel_performance_trends` returns perc30/perc70,
  no p75. The field name overstates what the tool returns.
- **`/mnt` paths survive and multiplied.** `SKILL.md` still directs to
  `/mnt/skills/public/frontend-design/SKILL.md`; the runbook now also writes every artifact
  to `/mnt/user-data/outputs/<slug>/`. Neither exists here.
- **`lint_composition.py` checks `debug-layout` on `<body>` only** — v1 places it on
  `#root`, and a sub-composition's renderable surface *is* `#root`, so a shipped debug
  overlay there passes the lint.
- **"Kim" appears twice** (`SKILL.md` model-tier note; `[S8/E-1]`) in a file that opens by
  declaring itself domain-neutral.
- **P-1 mandates ~10 `vidiq_score_title` calls (~50 credits).** On this channel the scorer
  has no discriminative power: it scored the failing target **95**, above all three
  diagnosis-driven rewrites (93 / 90 / 87), and the 2026-08-31 run found the same inversion
  on a different video (failing title 94, rewrites 83–87). Two runs, two videos.
