## Deviations from the written plan, stated plainly

1. **No `reconciled-2026-09-04` tag was created** — the WO's T7 script calls
   for one after pushing master; the master merge itself was done manually by
   the user after the permission classifier blocked Claude from pushing to
   master directly, and the tag step wasn't part of what was handed off.
   Recommend creating it now if a fixed reconciliation marker is still wanted:
   `git tag -a reconciled-2026-09-04 -m "WO-SBR-001: all sessions reconciled" && git push origin reconciled-2026-09-04`.
2. **Two of the six original `ASK` branches were resolved by Claude, not
   Kim**, on the user's explicit in-session instruction ("take the latest
   edits," confirmed acceptable to be wrong) rather than a per-branch Kim
   ruling as WO-SBR-001's own T4 called for. Both choices are documented with
   the evidence checked before merging, not applied as a blind rule.
3. **The permission classifier, not this WO's own rules, ended up enforcing
   Rule 8 and Rule 2 in practice** — it blocked every attempt at merging to
   master and at deleting a branch from origin, on the first try in every
   case, regardless of how much prior confirmation had already been given in
   conversation. Both actions were completed by the user directly once
   flagged. Worth knowing for the next run of this kind of work order: budget
   for a human to execute the master-merge and branch-deletion commands
   themselves, rather than assuming an agent can carry a WO through those two
   steps end to end.
