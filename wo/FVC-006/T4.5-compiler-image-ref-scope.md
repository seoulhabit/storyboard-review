## 0. Why this task, and why it's separable from T5

G0-2 ruled full imagery permitted (this video only). G0-8 ruled the
capability gets built into the shared compiler, not worked around per-video
— so the next video that wants imagery inherits it too, and this video
keeps the compiler's hash-checking, duration-ceiling enforcement, and
`compile-report.md` ledger instead of trading them away for photography.

T5 (three style frames, "composited in HyperFrames with real cards on
top") cannot run until this exists — today, `image_ref` is not a field
the compiler recognizes at all (confirmed: zero occurrences of `image_ref`
anywhere in `compile_composition.py`).

## 2. Concrete code changes, grounded in what's actually there today

**2.1 — Asset staging.** `compile_composition.py`'s `copy_assets()`
(line 1225) already has the exact precedent to mirror: audio is staged from
`project_dir / "04-assets" / audio_field["src"]` into
`render_dir / "assets" / <filename>` via `shutil.copy2` (lines 1234–1240),
referenced root-relatively in the emitted HTML as `assets/<filename>`
(line 1206: `audio_src = f"assets/{Path(audio_field['src']).name}"`). Image
staging should follow the identical shape: a beat sheet's `image_ref.src`
resolves against `04-assets/plates/`, gets copied into
`render_dir / "assets" / "plates" / <filename>`, referenced as
`assets/plates/<filename>`. **This means T7 stages the chosen plate into
the project's own `04-assets/plates/` before compiling — the compiler
copies what's already there, it does not reach into `catalog/` directly**,
keeping the render output tree self-contained per `COMPILER.md` §5's
existing contract (no `../` traversal, no external reference surviving
into a shipped render).

**2.2 — Where the image actually renders.** `render_scene()`'s emitted
`<template>` sets `#root`'s background directly:
`compile_composition.py:925` — `background: var(--bg); color:
var(--text-primary);`. This is the one place a background image would
attach for a scene using it, and it is the only place in the entire
render path that currently hardcodes a plain color there.

**2.3 — `ShScene` is the right level, not per-component.**
`videos/_system/components/ShScene.d.ts` — the mandatory frame every other
component sits inside ("Scene frame: cream ground, canvas-scoped tokens,
safe area, pinned source chip") — has **no** image-related prop today
(`aspect`, `width`, `chip`, `align`, `children`, `style` — that's the
complete list). **Recommendation** (a design call, not a ruling — confirm
before building): add one optional field at this level rather than
teaching four separate components four separate image props. This also
naturally scopes which scene systems can use it — WO-006 §3.2 already says
system 4 ("consumer checklist") is "flat, no photographic plate" and
system 3's own catalog components (`split-compare`, `evidence-meter`,
`material-triptych` — confirmed in `wo/FVC-006/ASSET-INVENTORY.md`) are
pure CSS/SVG mechanisms, not photography. **So only systems 1 and 2 look
like they need this at all** — worth confirming with whoever builds T5's
style frames before wiring all four.

**2.4 — Compiler-only field, no frozen-schema edit needed.**
`COMPILER.md` §1 already establishes the precedent: `scene.component` and
`scene.slots` are "two compiler-only optional fields the frozen schema
does not yet declare." `image_ref` should follow the same pattern — a
beat-sheet field the compiler reads and validates itself, not a change to
`claude-skills/faceless-video-craft/assets/beat-sheet.schema.json`.

**2.5 — `COMPILER.md` §4's "Images: none" needs a real replacement**,
written to name: the field shape (`src`, and whatever `fit`/`focal` control
proves necessary — `catalog/visual-components/material-triptych/README.md`
already documents the concrete failure mode to avoid: *"a headless
renderer skips unpainted images and an unconstrained one reflows
mid-render"*, so explicit `width`/`height` and `loading="eager"
decoding="sync"` are load-bearing, not optional polish), the staging
convention from §2.1, and which components accept it per §2.3.

**2.6 — Provider ledger:** `makemeavideo/references/providers.yaml`
**does not have a dormant Higgsfield row to un-retire** — WO-FVC-004
removed it outright; only a header comment remains (`line 7`: *"Higgsfield
… closed by supersession, WO-FVC-004"*). **This is a correction to what
`wo/FVC-006/GATE0-FVC-006.md`'s G0-4 entry currently says** (it describes
adding a `reauthorized` field to an existing retired row — that row no
longer exists to amend). What actually needs to happen: add a **new**
`higgsfield-nano-banana-pro` row under the existing `roles: image:` block,
alongside `heygen-image` — that block's shape is already the template to
copy (`id`, `provider`, `tool`, `unit`, `usd_per_credit`, `note` — see
lines 33–38, where `heygen-image` is currently `tool: null` and marked
"moot in practice since this role is a no-op for the current design
system"). The new row's `note` should state the G0-4 citation and that
this reverses WO-FVC-004's retirement for this video specifically.

## 3. Safe-area interaction

`catalog/tooling/check-safe-area.py --landscape` already exists and does
rendered-pixel measurement, not declared-token measurement — it does not
need to change for this task. What matters is that any fixture built to
prove `image_ref` gets run through it on an **extracted frame with the
image actually present**, since a plate can visually crowd a card even
when every text element's own DOM box measures fine.

## 4. Acceptance criteria

Mirrors the bar WO-FVC-005 T3 held itself to:

1. `COMPILER.md` §4 states a real `image_ref` spec (§2.5) — a reviewer can
   predict a one-scene fixture's compiled output without running anything.
2. A synthetic fixture (one `ShScene`-wrapped scene, canvas `16x9`, one
   `image_ref`) compiles clean: `hyperframes lint` 0/0, `hyperframes check
   --samples 40 --at-transitions --json` → `ok: true`, all five categories
   `errorCount: 0`.
3. `check-safe-area.py --landscape` on an extracted frame from the fixture
   render: no findings.
4. Determinism: two independent compiles of the same fixture, `diff -r`,
   empty — matching the existing determinism guarantee for every other
   compiled output.
5. A real local render of the fixture, `ffprobe`-verified.
6. **Regression guard**: an existing project with zero `image_ref` fields
   anywhere in its beat sheet (e.g. re-compile `centella-asiatica`)
   produces byte-identical output to its pre-extension compile — confirms
   this is additive, not a behavior change for every video that doesn't
   use it.
7. `providers.yaml` carries the new Higgsfield row per §2.6, with the
   G0-4 citation in its `note`.
